\section{RAID}

RAID (Vector Redundante de Discos Independientes) es un conjunto de unidades de disco físico vistas por el SO como una sola unidad o volumen lógico.

Con múltiples discos que funcionan en forma independiente y en paralelo, las distintas solicitudes de E/S se pueden gestionar en paralelo siempre que los datos solicitados residan en discos separados. Es más, una única petición de E/S se puede ejecutar en paralelo si el bloque de datos que se pretende acceder está distribuido a lo largo de múltiples discos. Por lo que RAID tiende a mejorar significativamente el rendimiento y/o fiabilidad del sistema de E/S a disco.

\section{RAID anidado}

Los RAID anidado (o \emph{nested RAID}) surgen de la idea de combinar dos niveles RAID para aprovechar simultáneamente sus ventajas. En lugar de aplicar un único nivel RAID directamente sobre un conjunto de discos físicos, se construye una jerarquía de arreglos.

Conceptualmente, el proceso consta de dos etapas:
\begin{enumerate}
  \item Se crean varios arreglos RAID de un determinado nivel utilizando los discos físicos.
  \item Esos arreglos se presentan al sistema como volúmenes lógicos (discos virtuales), sobre los cuales se aplica un segundo nivel RAID.
\end{enumerate}
Esto se ilustra en la figura \ref{fig:raid_anidado}.

\begin{figure}[!ht]
  \centering
  \begin{tikzpicture}[>=Stealth,font=\footnotesize]
    \node[text width=1.8cm, align=center] (D) {Discos Físicos};
    \node[text width=2.5cm, align=center,draw,rectangle,fill=gray!20,right=of D] (RI) {RAID de nivel inferior};
    \node[text width=2.5cm, align=center,draw,rectangle,fill=white!95!blue!93!green,right=of RI] (RS) {RAID de nivel superior};
    \node[text width=1.8cm, align=center,right=of RS] (F) {Volumen final};
    \draw[->] (D.east) -- (RI.west);
    \draw[->] (RI.east) -- (RS.west);
    \draw[->] (RS.east) -- (F.west);
  \end{tikzpicture}
  \caption{Primero se aplica el RAID de nivel inferior y luego el de nivel superior.}
  \label{fig:raid_anidado}
\end{figure}

De esta manera se tienen los siguientes tipos de RAID anidado:
\begin{itemize}
  \item RAID \(0+1\) (01): primero se crean arreglos RAID 0 y luego esos arreglos se espejan mediante RAID 1.
  \item RAID \(1+0\) (10): primero se crean espejos RAID 1 y luego se distribuyen los datos entre ellos mediante RAID 0.
  \item RAID \(5+0\) (50): primero se crean varios arreglos RAID 5 y luego se aplica RAID 0 sobre ellos.
  \item RAID \(6+0\) (60): primero se crean varios arreglos RAID 6 y luego se aplica RAID 0 sobre ellos.
\end{itemize}
Es importante destacar que el orden sí importa. Aunque los nombres puedan parecer similares, un RAID \(0+1\) y un RAID \(1+0\) no tienen la misma organización interna ni ofrecen exactamente la misma tolerancia a fallos.

\section{Sistemas de detección de errores}

La confiabilidad de un arreglo RAID no depende únicamente de la redundancia de datos, sino también de la capacidad de detectar fallas de forma temprana y precisa. Para ello, coexisten dos niveles de diagnóstico: el autodiagnóstico interno del disco mediante S.M.A.R.T. y la supervisión externa realizada por la controladora RAID.

\subsection{Tecnología S.M.A.R.T.}

S.M.A.R.T. (\textit{Self-Monitoring, Analysis and Reporting Technology}) es un sistema de autodiagnóstico incorporado en el firmware de discos duros y unidades de estado sólido. Su objetivo principal es detectar signos de deterioro progresivo antes de que ocurra una falla catastrófica.

Cada dispositivo mantiene internamente un conjunto de atributos que describen su estado de salud. Los más relevantes son:
\begin{itemize}
  \item \textit{Reallocated Sector Count:} sectores defectuosos reasignados a la zona de reserva.
  \item \textit{Current Pending Sector:} sectores inestables pendientes de reevaluación.
  \item \textit{Uncorrectable Read Errors:} errores de lectura no recuperables.
  \item \textit{Power-On Hours (POH):} tiempo total de funcionamiento.
  \item \textit{Power Cycle Count:} ciclos de encendido/apagado.
  \item \textit{Temperature:} temperatura operativa.
  \item \textit{UltraDMA CRC Error Count:} errores de comunicación en la interfaz.
\end{itemize}
El principio de funcionamiento es el siguiente:
\begin{enumerate}
  \item El disco intenta leer un sector.
  \item El firmware detecta errores en la lectura.
  \item Intenta corregirlos mediante códigos ECC internos.
  \item Si el sector es defectuoso, lo reasigna a un sector de reserva.
  \item Se incrementa el contador S.M.A.R.T. correspondiente.
\end{enumerate}
Todo el proceso ocurre dentro del disco, sin intervención del sistema operativo, lo que permite una advertencia predictiva.

\subsection{Detección de fallas en una controladora RAID}

Además del sistema S.M.A.R.T. la controladora RAID también cuenta con sistemas para la detección de fallos de unidades de almacenamiento.

\subsubsection{1. Errores de Entrada/Salida}
Si un disco devuelve errores sostenidos de lectura/escritura, tras varios reintentos la controladora lo marca como \texttt{Failed}.
\begin{verbatim}
Controladora  -> Leer bloque 5821
Disco         -> Error
Controladora  -> Reintentar
Disco         -> Sin respuesta
Controladora  -> Disco marcado como Failed
\end{verbatim}

\subsubsection{2. Detección por Timeouts}
Un disco que tarda varios segundos intentando recuperar un sector degrada todo el arreglo. Por ello las controladoras establecen tiempos máximos de espera. Si se superan, la operación se aborta y se contabiliza como fallo.

\subsubsection{3. Verificación de consistencia}
En RAID con paridad (RAID 5/6), la controladora ejecuta periódicamente un \textit{Consistency Check}: lee todos los bloques, recalcula la paridad y la compara con la almacenada. Permite detectar \textit{silent data corruption}.

\subsubsection{4. Monitoreo S.M.A.R.T. e integración predictiva}

Es el punto de unión entre ambos sistemas. La controladora consulta periódicamente S.M.A.R.T.:
\begin{verbatim}
SMART Status:
  Reallocated sectors = 850
  Pending sectors     = 230
Estado: Predicted Failure
\end{verbatim}
Aunque el disco aún funcione, la controladora puede: generar alarma, marcarlo como Predictive Failure, activar un Hot Spare e iniciar una reconstrucción preventiva.

No todas las controladoras lo implementan igual: las de gama alta lo integran nativamente en su software de gestión, mientras que algunas implementaciones simples o RAID por software delegan la consulta al SO mediante herramientas como \texttt{smartmontools}.
